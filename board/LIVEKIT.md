# Пилот видеосвязи для занятия

1. Создайте DNS-записи для `video.prosto5.ru` и `turn.prosto5.ru`, указывающие на IP VPS. Установите LiveKit Server как отдельный сервис на VPS. Сгенерируйте отдельные ключ и секрет и храните конфигурацию с ограниченными правами. Параметры для конфигурации LiveKit:

   ```yaml
   port: 7880
   bind_addresses: ["127.0.0.1"]
   rtc:
     use_external_ip: true
     tcp_port: 7881
     udp_port: 7882
   room:
     auto_create: false
   keys:
     YOUR_API_KEY: YOUR_API_SECRET
   turn:
     enabled: true
     domain: turn.prosto5.ru
     tls_port: 5349
     udp_port: 3478
     cert_file: /path/to/turn-fullchain.pem
     key_file: /path/to/turn-privkey.pem
   ```

   Откройте входящие 7881/TCP, 7882/UDP, 3478/UDP и 5349/TCP в сетевом экране. Для TURN нужен сертификат его домена, доступный сервису, и перезапуск либо обновление сертификата в сервисе при продлении. TCP 5349 может быть закрыт в ограниченных клиентских сетях. TURN/TLS на 443 в таком случае требует отдельного IP или отдельной точки входа, поскольку 443 уже занят Nginx.

2. Настройте отдельный HTTPS-блок Nginx для `video.prosto5.ru` с сертификатом этого имени. В его `location /` добавьте:

   ```nginx
   proxy_pass http://127.0.0.1:7880;
   proxy_http_version 1.1;
   proxy_set_header Host $host;
   proxy_set_header Upgrade $http_upgrade;
   proxy_set_header Connection "upgrade";
   proxy_read_timeout 3600s;
   ```

   Проверьте `nginx -t` и перезагрузите конфигурацию. Порт 7880 должен оставаться локальным.

3. Выполните обычный деплой сайта и обновите сборку встроенной доски по [инструкции сборки](README.md). Добавьте в окружение сервиса сайта `LESSON_CALL_URL=wss://video.prosto5.ru`, `LESSON_CALL_KEY` и `LESSON_CALL_SECRET` с теми же значениями, что в LiveKit. Перезапустите сервис сайта. Для отдельной пробной доски без привязки к занятию вызов недоступен.
4. Видеосвязь доступна для всех запланированных занятий с доской. После открытия доски в разрешённое время звонок подключается автоматически и запрашивает микрофон. Камера остаётся выключенной. Проверьте звонок из двух сетей, отказ в разрешении микрофона, повторное подключение и кнопку «Выйти из урока». При ручном выходе из звонка повторное подключение выполняется кнопкой «Видеосвязь». Просмотр проведённого занятия открывается без автоматического звонка. Проверьте, что ученик другого занятия не может подключиться. Во время проверки сравните CPU, RAM и трафик сервера с обычным уроком. Для отдельной проверки TURN убедитесь по статистике WebRTC, что выбран маршрут с кандидатом типа relay.

[Настройка сети LiveKit](https://docs.livekit.io/transport/self-hosting/ports-firewall/) · [Образец конфигурации LiveKit](https://github.com/livekit/livekit/blob/master/config-sample.yaml)

## Связь с двух устройств

Доску можно одновременно открыть на компьютере и планшете под одной учётной записью. Звук и видео работают на одном устройстве: второе получает сообщение «Связь на другом устройстве» и кнопку «Перенести сюда». На телефоне перенос также доступен значком устройства со стрелкой и в панели связи.

При явном переносе старое устройство отключается от звонка и показывает «Связь перенесена на другое устройство», сохраняя доступ к рисованию. Состояние микрофона берётся из действующего звонка; камера нового устройства остаётся выключенной. Если браузер не разрешил микрофон, его можно включить вручную. Автоматического обратного перехвата нет.

Для обновления нужны одновременно новый серверный `lesson_call.py` и новая сборка доски; настройки LiveKit и ключи менять не требуется. Проверьте перенос в обе стороны, с включённым и выключенным микрофоном, открытие второй доски без переноса, а также отсутствие доступа у постороннего ученика. При обрыве подключения во время входа серверная бронь может сохраняться до минуты; кнопка явного переноса позволяет подключиться сразу.
