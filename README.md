# Круг Пи

Сайт «Круг Пи»: занятия по математике и подготовка к ОГЭ и ЕГЭ.
Сервер — Python + FastAPI, интерфейс — HTML, CSS и JavaScript.

Доступен REST API `GET /api/health`. Вход, выход, смена пароля и профиль доступны в личном кабинете.
Аккаунты учеников создаёт администратор; публичная регистрация закрыта.
Учебные материалы пока показывают статус разработки. Заявки сохраняются через `POST /api/trial-requests` в SQLite.

## Первый запуск в PyCharm

1. После слияния Pull Request клонируйте репозиторий через
   **Get from Version Control** или **Git → Clone**:
   `https://github.com/bondarenko-petr/petrmath.git`.
   Выберите новую пустую папку, например `PycharmProjects/petrmath`.
   Существующий проект `math-website` можно сохранить отдельно.
2. Создайте виртуальное окружение `.venv` в корне клонированного проекта
   и выберите его Python-интерпретатор в настройках PyCharm.
3. В Terminal из корня проекта установите зависимости:

   ```bash
   .venv/bin/python -m pip install -r requirements.txt
   ```

4. Откройте `run.py` и выберите **Run 'run'**.
5. Откройте http://127.0.0.1:8000/.

Проверка сервера: http://127.0.0.1:8000/api/health.
Интерактивная документация API: http://127.0.0.1:8000/docs.

Остановка — кнопка Stop. Изменения Python-кода перезапускают сервер.
После правок HTML/CSS/JavaScript обновите страницу браузера.
Если порт 8000 занят, остановите прежний сервер или измените порт в `run.py`.

## Запуск через Terminal

На macOS/Linux из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m uvicorn main:app --reload --host 127.0.0.1 --port 8000
```

Если окружение уже создано, первую команду пропустите.
Остановка — Ctrl+C. Сервер предназначен для локальной разработки.

## Как получать изменения

Изменения публикуются в отдельных ветках `codex/...` через Pull Request.
Проверьте Pull Request на GitHub и выполните **Merge**, когда готовы принять его.
Затем из корня локального клона на ветке `main`:

```bash
git pull --ff-only origin main
.venv/bin/python -m pip install -r requirements.txt
```

Перед обновлением сохраните собственные изменения коммитом или через Git Stash.
Если обновление не может выполниться без слияния, Git остановится:
не удаляйте свои правки, сначала разберите расхождения.
Перезапустите сервер после обновления зависимостей.

## Заявки на пробный урок

Форма сохраняет имя, email, телефон, выбранные направления, комментарий,
согласие и время заявки в `data/trial_requests.sqlite3`. База создаётся
автоматически и исключена из Git. Перезапуск сервера не удаляет заявки.
Уведомления на почту или в Telegram не отправляются.

Просмотреть заявки локально можно в SQLite-клиенте (например, DB Browser for SQLite)
или через Terminal:

```bash
sqlite3 -header -column data/trial_requests.sqlite3 'SELECT * FROM trial_requests ORDER BY id DESC;'
```

База находится вне публичного каталога сайта. Переменная `TRIAL_REQUESTS_DB`
позволяет выбрать другой путь к базе, например на постоянном диске сервера.

## Подключение MySQL локально

Интеграция использует официальный MySQL Connector/Python:
https://dev.mysql.com/doc/connector-python/en/connector-python-connectargs.html

1. Установите MySQL Community Server с https://dev.mysql.com/downloads/mysql/
   и запустите сервер. Для удобного просмотра таблиц можно установить MySQL Workbench.
2. Обновите зависимости проекта:

   ```bash
   .venv/bin/python -m pip install -r requirements.txt
   ```

3. В MySQL Workbench подключитесь локально как администратор и выполните
   содержимое `sql/mysql.sql`: появятся база `krug_pi` и таблица `trial_requests`.
4. Создайте отдельного пользователя приложения. Замените пример пароля своим:

   ```sql
   CREATE USER 'krug_pi_app'@'127.0.0.1' IDENTIFIED BY 'replace_with_your_password';
   GRANT INSERT, SELECT ON krug_pi.trial_requests TO 'krug_pi_app'@'127.0.0.1';
   ```

5. Скопируйте `.env.example` в `.env` в корне проекта:

   ```bash
   cp .env.example .env
   ```

   Укажите `MYSQL_PASSWORD` и, при необходимости, остальные параметры.
   `.env` автоматически читается при запуске и исключён из Git.
   Настройки окружения PyCharm имеют приоритет над `.env`.
6. Перезапустите `run.py`, отправьте заявку и проверьте её в Workbench:

   ```sql
   SELECT * FROM krug_pi.trial_requests ORDER BY id DESC;
   ```

Без настройки `DB_BACKEND` сайт продолжает использовать SQLite.
С `DB_BACKEND=mysql` ошибки MySQL возвращают HTTP 503: незаметного переключения
на SQLite нет. Старые заявки SQLite не удаляются и автоматически не переносятся.
Файл `sql/mysql.sql` создаёт таблицу заранее: приложение не требует прав CREATE.
После подключения MySQL данные хранятся на сервере MySQL, а не в файле SQLite.

## Регистрация, вход и профиль

После обновления выполните **весь `sql/accounts.sql` через подключение root**
в PyCharm. Он добавит таблицы `users` и `sessions` и права для `krug_pi_app`,
не изменяя заявки. Затем перезапустите `run.py`.

Кнопки входа и личного кабинета открывают `/account.html`. На телефоне личный
кабинет доступен через меню. Новый ученик получает роль `student`; роль администратора назначается отдельно. Профиль показывает имя,
email и роль. Редактирование профиля, подтверждение почты, восстановление
пароля через email и материалы пока не реализованы. Расписание и учёт оплат описаны ниже.

Пароли хешируются scrypt с индивидуальной солью. Сессии действуют семь дней,
в базе хранится только SHA-256 токена. Выход отзывает сессию на сервере.
Cookie имеет HttpOnly и SameSite=Lax; для HTTPS-хостинга установите
`COOKIE_SECURE=true` в `.env`. POST-запросы авторизации требуют заголовок
`X-Requested-With: KrugPi` (страница добавляет его автоматически).
Ограничение входа и регистрации: десять попыток в минуту на IP в рамках одного
процесса. При масштабировании потребуется общий ограничитель и настройка
доверенного прокси. Не публикуйте сайт по HTTP с рабочими аккаунтами.

REST API: `POST /api/auth/register`, `POST /api/auth/login`,
`GET /api/auth/me`, `POST /api/auth/logout`.

Проверки: `.venv/bin/python -m unittest discover -s tests -v`.

## Кабинет администратора

Администратор входит через ту же страницу `/account.html`. Для назначения роли:
откройте `sql/admin.sql` в PyCharm, замените **оба** значения
`REPLACE_WITH_YOUR_EMAIL` на email своего зарегистрированного аккаунта
и выполните файл через подключение MySQL `root`.
Проверьте, что SELECT показывает именно ваш аккаунт с ролью `admin`.
Не публикуйте отредактированный файл с личным email; исходный файл остаётся шаблоном.

Обновите страницу профиля: появятся роль «Администратор» и ссылка на
`/admin.html`. Кабинет показывает заявки и зарегистрированных учеников,
по 20 записей на странице. Управление учениками, расписанием и оплатами описано ниже.
Права проверяются сервером на каждом запросе; парольные хеши и токены
не возвращаются. Ученик получает 403, посетитель без входа — 401.
Права пользователя MySQL `krug_pi_app` уже включают SELECT на эти таблицы;
дополнительные GRANT для кабинета не требуются.

REST API: `GET /api/admin/students`, `GET /api/admin/trial-requests`.
Для снятия роли выполните через root:
`UPDATE krug_pi.users SET role='student' WHERE email='YOUR_EMAIL';`.

## Структура интерфейсов по REQUIREMENTS.md

Кабинет ученика включает ближайшее занятие, текущую неделю, домашние задания,
материалы и состояние оплат (раздел 11). Кабинет администратора включает
обзор, расписание, учеников, проверку работ, финансы и настройки (раздел 10).
Реальные данные сейчас доступны только для профиля, заявок и списка учеников.
Остальные блоки явно показывают, что соответствующие функции ещё не подключены;
выдуманные занятия, оценки и финансовые показатели не отображаются.

Раздел 3 реализован для создания учеников: логин, временный пароль и
обязательная смена. Прежние аккаунты сохраняют email в качестве логина.
Назначение первого администратора отдельной командой остаётся отложенным.

## Управление учениками

После обновления выполните **весь `sql/student_management.sql` через root**
(после `accounts.sql`). Скрипт добавляет логины, активность аккаунтов, обязательную
смену пароля, таблицу `student_profiles` и права UPDATE приложения.
Таблицы и существующие пароли не удаляются. Старые аккаунты входят по прежнему
email, который становится их логином. Перед миграцией сохраните резервную копию базы.
При запуске скрипта в PyCharm используйте режим выполнения всего SQL-файла,
который обрабатывает DELIMITER и процедуру миграции.

В кабинете администратора выберите «Ученики» → «Добавить ученика».
Укажите имя, уникальный логин (3–40 символов: латиница, цифры, `.`, `_`, `-`),
контакты, класс, цену в рублях и длительность в минутах. Цена хранится в копейках,
длительность — от 1 до 1440 минут. Email необязателен. При редактировании старого
аккаунта ученика с email-логином выберите новый логин по указанным правилам.

После создания или сброса пароля интерфейс один раз показывает логин и
временный пароль. Передайте их ученику вручную и закройте блок. Пароль
не сохраняется в браузерном хранилище и не попадает в базу в открытом виде.
Если пароль не был скопирован, выполните сброс и выдайте новый.
Ученик обязан сменить временный пароль до открытия своего кабинета.
Администратор также может сменить собственный пароль в профиле.

«Архивировать» блокирует вход и отзывает сессии; данные остаются в базе.
«Восстановить» вновь разрешает вход. Сброс пароля завершает все старые сессии
и снова требует смены пароля. Физическое удаление ученика не предусмотрено.

Создание первого администратора отдельной командой остаётся отложенным.
Существующий администратор сохраняет доступ после миграции.

## Необязательная отправка временного пароля на email

Временные пароли теперь содержат 8 случайных букв/цифр без `0/O`, `1/I/l`.
Обязательная смена при первом входе сохранена. Это временный пароль,
а не автоматически истекающий код: срок действия по времени пока не введён.

Укажите email при создании/редактировании ученика. После создания или сброса
в блоке выданных данных появится «Отправить на email ученика».
Перед отправкой подтверждается адрес; отправка сама по себе не сбрасывает пароль.
Письмо содержит ссылку на вход, логин, временный пароль и инструкцию по смене.
Пароль не сохраняется в открытом виде на сервере; для отправки используется
значение из текущего блока выдачи. Если блок закрыт, новый пароль получают сбросом.

Настройте в `.env` SMTP_HOST, SMTP_PORT, SMTP_SECURITY (`ssl` для 465 или
`starttls` для 587), SMTP_USER, SMTP_PASSWORD, SMTP_FROM и SITE_URL.
SMTP_FROM — полный email отправителя, SITE_URL — реальный HTTPS-адрес сайта,
доступный ученикам. Локальный адрес 127.0.0.1 из письма не откроет ваш сайт у ученика.
У почтового провайдера может понадобиться отдельный пароль приложения.
Не публикуйте значения SMTP_PASSWORD в Git.

Настройки отсутствуют — отправка показывает ошибку настройки, но ручная передача
остаётся доступной. Ответ об успехе означает принятие SMTP-сервером,
а не подтверждение доставки в почтовый ящик; проверьте также папку «Спам».
Это отдельная опция выдачи аккаунта по запросу, не автоматические напоминания
о занятиях из отложенных требований.

## Расписание и занятия

После обновления кода остановите сервер и сделайте резервную копию MySQL.
Под пользователем root выполните **весь** файл `sql/lessons.sql` в PyCharm
(после `sql/student_management.sql`). Скрипт повторно запускается безопасно:
существующие данные не удаляются. Он создаёт `lessons`, `lesson_series`,
строку блокировки расписания и выдаёт приложению необходимые права.
SQLite создаёт таблицы автоматически. Реальную MySQL-миграцию перед запуском
рекомендуется сначала проверить на копии базы.

В `.env` можно добавить `LESSON_TIMEZONE=Europe/Moscow`. Это IANA-часовой пояс
расписания и кабинетов; например, `Europe/Berlin`. Перезапустите сайт.
Время хранится в UTC, а в интерфейсе явно указан часовой пояс. Серии сохраняют
местное время при переходе на летнее/зимнее время; неоднозначное или несуществующее
время отклоняется. При изменении часового пояса существующие UTC-моменты не меняются.

Администратор открывает «Расписание» в своём кабинете. Выбирает активного
ученика, дату и время, тему и необязательную HTTPS-ссылку на онлайн-урок.
Цена и длительность подставляются из профиля, но сохраняются отдельно в уроке.
Для серии отметьте дни недели и последнюю дату включительно, в пределах года.
Пересечения занятий преподавателя запрещены; соседние уроки могут идти подряд.

Недельный календарь показывает всех учеников. В разделе «Все занятия и история»
доступны фильтры по датам и ученику, перенос, отмена, восстановление, отметка
«Проведено» и удаление ошибочных будущих записей. Серия меняется для одного урока,
этого и следующих либо всех будущих уроков серии; прошлые/проведённые сохраняются.
Перенос серии сдвигает местное время всех выбранных уроков на одинаковую величину.
Новую периодичность задают новой серией, предварительно отменив/удалив старые будущие уроки.

Ученик видит только свои ближайшие занятия, текущую неделю и историю, без
управления расписанием. До обязательной смены временного пароля доступ закрыт.

Google Calendar пока не подключён: этот этап реализует расписание в базе сайта.
Односторонняя OAuth-синхронизация с календарём преподавателя остаётся отдельным
следующим этапом; ничего не отправляется в Google или ученикам автоматически.
Домашние задания и материалы остаются следующими этапами. Учёт оплат описан ниже.


## Оплаты и баланс

Страница `/finance.html` доступна из раздела «Финансы» администратора
и из карточки оплат в кабинете ученика. Администратор выбирает ученика,
вносит сумму полученной оплаты; количество уроков необязательно. Это ручной
учёт: банковские платежи и возвраты сайт не выполняет.

### Обновление MySQL

Перед первым использованием сделайте резервную копию базы, затем выполните
**весь** `sql/finance.sql` в MySQL от имени root после миграции `sql/lessons.sql`.
Файл добавляет таблицу `payments` и права приложения; существующие записи
не удаляются. Если имя базы или пользователь приложения отличаются от
`krug_pi` / `krug_pi_app`@`127.0.0.1`, адаптируйте USE и GRANT перед выполнением.
В SQLite таблица создаётся автоматически при подключении.

Пример из Terminal в корне проекта (пароль вводится в приглашении MySQL):

```bash
mysqldump -u root -p --single-transaction krug_pi > ~/krug_pi_before_finance.sql
mysql -u root -p < sql/finance.sql
```

Перезапустите сервер и обновите страницу. Отсутствие миграции MySQL вернёт
ошибку недоступной базы; интерфейс не показывает выдуманные нулевые балансы.

### Денежный баланс и расчёт количества уроков

Денежный баланс — источник истины: сумма действующих оплат минус цены
проведённых уроков. Цена берётся из самого занятия, не из текущего профиля.
Отмена и перенос деньги не списывают; отрицательная сумма означает задолженность.
Ранее проведённые занятия тоже учитываются: внесите прежние оплаты для верного остатка.

В `/finance.html` по умолчанию выбрано «Пополнить баланс — только сумма».
Количество уроков не требуется. Для частичной оплаты или погашения долга
введите только полученную сумму. Режим «Рассчитать сумму по количеству уроков»
подставляет количество × текущую цену. Итоговую сумму можно изменить вручную.
Количество в записи пакета сохраняется для истории, но не является отдельным
балансом или гарантией определённого числа занятий по скидочной цене.
Списание идёт по стоимости каждого урока в расписании.

Оценка доступных полных уроков = положительный денежный остаток, делённый
на текущую цену урока с округлением вниз. Например, 5 000 ₽ при цене 1 500 ₽
хватит на 3 урока, остаток 500 ₽. Если текущая цена не задана или равна нулю,
показана сумма без оценки количества. Задолженность всегда показывается деньгами,
а оценка доступных уроков при долге равна нулю. Изменение текущей цены меняет
только оценку, но не переписывает прежние оплаты и стоимость проведённых уроков.

**Обновление MySQL:** после резервной копии базы выполните весь
`sql/finance_amount_only.sql` под root после `sql/finance.sql`.
Он разрешает не указывать количество в оплате; суммы, номера, прежние пакеты
и история отмен сохраняются. SQL-файл можно выполнить повторно. SQLite
обновляется автоматически и сохраняет все строки в одной транзакции.
После обновления перезапустите сервер и обновите страницу браузера.

Повторный `request_id` оплаты и повторная отметка «Проведено» не создают
дополнительных списаний или зачислений. Ошибочную запись оплаты можно отменить
с причиной; она остаётся в истории, но исключается из суммы. Это отмена записи,
а не банковский возврат. Ученик видит только свои данные без права изменений.

Проверка: `python -m unittest discover -s tests -v`. Тесты используют временную
SQLite-базу; реальную миграцию и подключение MySQL проверяйте отдельно.


## Обработка заявок на пробный урок

В кабинете администратора заявки представлены компактными раскрывающимися
строками. По нажатию видны контакты, сообщение, статус и заметка администратора.
Поиск работает по имени, email или телефону; доступны фильтр статуса и пагинация.

Перед первым использованием на MySQL сделайте резервную копию базы и выполните
**весь `sql/trial_management.sql` через подключение root** после `sql/accounts.sql`.
Он добавляет отдельную таблицу обработки заявок и права приложения; исходные
заявки не меняет и не удаляет. Если вы используете другое имя базы/пользователя,
адаптируйте USE и GRANT. В SQLite таблицы создаются автоматически.

Вкладка «В работе» содержит статусы «Новая», «Связываемся» и «Пробный назначен».
Статусы «Стал учеником» и «Закрыта» перемещают заявку в «Архив».
Для закрытия нужна причина: «Передумали», «Нет ответа», «Дубль», «Спам» или
«Другое». Кнопка «В архив» предлагает выбрать причину; затем нажмите «Сохранить».
Из архива можно вернуть заявку в работу: заметка и контакты сохраняются.
Статусы не создают аккаунты и занятия автоматически — используйте для этого
разделы «Ученики» и «Расписание». Счётчики вкладок показывают общее число заявок,
а количество под заголовком — результат текущего поиска и фильтра.

Ранее полученные заявки отображаются как новые. Функции окончательного удаления
и автоматического закрытия по времени не добавлены. При редактировании одной
заявки в двух окнах устаревшая версия не перезаписывает новую заметку:
сохраните свой текст отдельно и обновите список.
